# T4 · Fixtures/TC-*.json + ground_truth.json — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crear los 12 fixtures JSON que validan contra `ExtractedInvoice` (T2), `ground_truth.json` con veredictos esperados y dependencias, y un PDF escaneado como artefacto para la demo.

**Architecture:** 12 archivos `fixtures/TC-XX.json` (cada uno un `ExtractedInvoice` válido) + `fixtures/ground_truth.json` (orquestación: veredicto esperado, reason_code, dependsOn). Sin código TypeScript nuevo. La verificación es `ExtractedInvoice.safeParse(fixture).success === true` para cada fixture, ejecutada con un script de validación.

**Tech Stack:** JSON, Zod (via tsx para validación), Node 22.

**Spec:** `docs/superpowers/specs/2026-10-17-t4-fixtures-design.md` — el plan implementa ese spec; los dos viajan juntos.

## Global Constraints

- Los fixtures viven en `fixtures/` (raíz del repo, no en `api/`).
- Cada `TC-XX.json` es un `ExtractedInvoice` puro: solo los campos del schema de T2. Sin `file_name`, `file_hash`, `expected_verdict`, ni metadata.
- `ground_truth.json` lleva `expected_verdict`, `expected_reason_code` y `dependsOn` por TC.
- Todos los campos opcionales se incluyen con valores coherentes (subtotal + tax_amount = total_amount; quantity × unit_price = total por línea).
- `field_confidence` solo en TC-12 (con `due_date: 0.5`). Los demás no lo incluyen.
- Nombres ficticios coinciden con los proveedores del seed de T3 (tax_id exacto).
- Monedas válidas: USD, MXN, COP, EUR.
- Fechas en formato `YYYY-MM-DD`.
- `just check` y `just fmt` limpios. Los fixtures JSON se formatean con Prettier (2 espacios).
- Commits: Conventional Commits, mensajes en inglés, un commit = un cambio lógico.

## Review Focus

Cinco formas de falla que el spec implica y que ningún test toca.

1. **Un fixture que no valida contra `ExtractedInvoice`.** Si un campo tiene el tipo equivocado (string en vez de number, fecha mal formada), el runner falla al cargarlo. Mitigación: script de validación que parsea cada fixture con `ExtractedInvoice.safeParse()` y reporta cuáles fallan.
2. **Un `vendor_tax_id` que no existe en el seed.** Si TC-05 usa un tax_id que accidentalmente coincide con un proveedor del seed, la regla 4 no dispara. Mitigación: verificar que TC-05 y TC-08 usan tax_ids que no están en el seed (o que TC-08 omite `vendor_tax_id`).
3. **`field_confidence` en un fixture que no es TC-12.** Si un fixture accidentalmente incluye `field_confidence`, el motor podría evaluar la regla 1. Mitigación: script de validación que verifica que solo TC-12 tiene `field_confidence`.
4. **Montos incoherentes.** Si `subtotal + tax_amount ≠ total_amount`, el motor podría detectar inconsistencia. Mitigación: verificar coherencia al crear cada fixture.
5. **TC-03 sin dependencia declarada.** Si `ground_truth.json` no declara `dependsOn: ["TC-01"]` para TC-03, el runner no monta el pre-estado y TC-03 no detecta el duplicado. Mitigación: verificar que TC-03 y TC-10 tienen `dependsOn` correctos.

### Task 5: Verificación

- [ ] **Step 1: Validar que todos los fixtures pasan `ExtractedInvoice.safeParse()`**

Escribir un script temporal `api/src/_validate_fixtures.ts`:

```ts
import { readFileSync, readdirSync } from "node:fs";
import { join } from "node:path";
import { ExtractedInvoice } from "./domain/extraction.js";

const dir = join(process.cwd(), "..", "fixtures");
const files = readdirSync(dir).filter((f) => /^TC-\d+\.json$/.test(f)).sort();

let ok = true;
for (const file of files) {
  const raw = JSON.parse(readFileSync(join(dir, file), "utf-8"));
  const result = ExtractedInvoice.safeParse(raw);
  if (!result.success) {
    console.error(`FAIL ${file}:`, result.error.issues.map((i) => `${i.path.join(".")}: ${i.message}`).join("; "));
    ok = false;
  } else {
    console.log(`OK   ${file}`);
  }
}
console.log(ok ? "\nTodos los fixtures validan." : "\nHay fixtures inválidos.");
process.exit(ok ? 0 : 1);
```
